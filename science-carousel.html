How It Works

Five things that make a carousel work.

Swipe through how a Science Carousel™ gets built.

01 · Start from the story

The argument already exists. This is it, in stills.

If we have built your Science Story™ or an MOA Moment™, the hard part is done: the mechanism is written, verified and already explained in a way people follow. The carousel is that same argument rebuilt for the one place every shopper actually looks.

What carries over

  • The mechanism, already verified
  • Claims already through review
  • The visual system from the video
  • Starting the science from scratch
02 · Every image stands alone

You do not control the running order. So we stop depending on it.

Amazon states plainly that it selects and arranges the images shown on a product page, and that the order in Image Manager may not match what a shopper sees. Brand owners can also run image experiments that change which image leads.

So a carousel built as slide one, slide two, slide three is a carousel built on an assumption. Each image in a Science Carousel™ carries one complete idea and reads correctly wherever it lands.

Two ways to build a set

SequentialFragile

Image 3 only makes sense after image 2. Reorder it and the argument breaks.

Self-containedDurable

Each image lands one idea on its own. Any order still sells.

03 · Built for a thumb

Read at the size it is actually seen.

Most of this gets viewed on a phone, where the carousel becomes a swipe and every image is competing with a thumbnail-sized first impression. Type is set to survive that, and the single idea in each frame has to land before anyone decides to keep swiping.

Mobile rules we hold

  • One idea per frame
  • Legible at thumbnail size
  • No copy that needs zoom to read
  • Dense paragraphs of body text
04 · Continuity across the gaps

A set that reads as one system, in any order.

Retail platforms frame every image in their own white border, so the images never touch. Continuity has to come from inside the frames: a shared palette, a repeated structure, graphical elements that carry from one image into the next. That is what makes six separate files look like one piece of work.

What ties the set together

Shared colour systemRepeated layout gridCarried graphical motifOne type hierarchyNumbered slides“Continued” arrows
05 · Spec-clean on delivery

Right to each platform’s rules, first time.

Every retailer publishes its own image requirements, and a set that fails them does not go live. We deliver to spec per platform, with the source files so your team can adapt them later without coming back to us.

FAQ

Common questions

How many images are in a Science Carousel™?

Five to six. Enough to carry a complete mechanism story, few enough that every frame earns its place. Retailers vary in how many images they display before a shopper has to click or swipe for the rest, so the strongest ideas go early.

Can we control the order the images appear in?

Not entirely, and that is the reason this exists. Amazon documents that it selects and arranges the images shown on a product page, and that the order in Image Manager may not match what a shopper sees. Brand owners can also run image experiments that change which image leads. So we build every frame to stand on its own rather than depending on a sequence you do not control.

Do we need a video or a Science Story™ first?

It helps, because the mechanism and the claims are already built and approved. But no. If you have substantiated claims we can build the set from those, and if you do not, that is what Science Intelligence™ is for.

Which retailers can you build for?

Any product page you sell on. Amazon and Walmart publish detailed image requirements and we build to them directly. Target, Chewy and other retail partners publish their own specs through their vendor portals, and we work to whichever apply to your account, alongside your own DTC site.

Can we put claims on the images?

Yes, within two sets of rules. Your claims still need to clear MLR the same way they would anywhere else, and each retailer bans certain content on product images, including things like pricing callouts, review or award imagery, and platform badges. We build inside both.
